## Intent and Context

Create the bun-managed Solid.js + TypeScript SPA skeleton under `web/`. It must contain every page route as a compilable stub, so the three screen plans (PF-11, PF-12, PF-13) can fill disjoint files in parallel, plus the shared API client and pure-TS libraries with `bun test` coverage. The SPA talks to `/auth/session`, `/v1/...` and `/admin/api/...` with the session cookie and the `X-Punchflow-CSRF` header. The Go side embeds `web/dist/app` (built by `vite build`); `web/dist/.gitkeep` is owned by PF-01.

## Non-goals

- No real screen content (stubs only; screens are PF-11..13).
- No npm/yarn/pnpm commands or lockfiles. No OIDC library (login is server-side).
- Do not create or touch `web/dist/` (PF-01 owns `web/dist/.gitkeep`; build output goes to `web/dist/app`).

## Contracts

- `package.json` scripts: `"build": "vite build"`, `"typecheck": "tsc --noEmit"`, `"dev": "vite"`. Dependencies: `solid-js`, `@solidjs/router`; devDependencies: `vite`, `vite-plugin-solid`, `typescript`, `@types/bun`. Pin exact versions (no `^`). Nothing else.
- `vite.config.ts`: `plugins: [solid()]`, `build.outDir: "dist/app"`, `build.emptyOutDir: true`, `base: "/"`; dev server proxy for `/v1`, `/admin/api`, `/auth`, `/files` to `http://localhost:8080`.
- `tsconfig.json`: `strict: true`, `jsx: "preserve"`, `jsxImportSource: "solid-js"`, `types: ["bun"]`, `noEmit: true`, include `src`.
- `App.tsx` routes (path -> page; lazy imports): `/login`, `/`, `/tickets`, `/tickets/new`, `/tickets/:id`, `/tickets/:id/edit` (TicketEdit for both new/edit), `/workflows`, `/workflows/:id`, `/routes`, `/routes/:id`, `/admin/users`, `/admin/org`, `/admin/grades`, `/admin/roles`, `/admin/masters`, `/admin/classification`, `/admin/proxies`, `/admin/audit-logs`, `/settings/tokens`, `/admin/service-accounts`, `/admin/webhooks`, `/admin/webhooks/:id/events`, `/admin/dev`. ## Key Points and Pitfalls

- `apiFetch` sends `credentials: "same-origin"`, `Content-Type: application/json` only when there is a body, and `X-Punchflow-CSRF` on POST/PATCH/DELETE when a token is set. A non-2xx response with a JSON body becomes `KickflowError` (`code`, `message`, `errors`); a 411 or empty body becomes `KickflowError` with `code: "http_<status>"`.
- `toTicketInputs` must emit an entry for every form field (kickflow requires all fields): checkbox -> string array; master/user/team/ticket -> `generalMasterItemId`/`userId`/`teamId`/`ticketId`; file -> `files` (signed ids); calculation -> `value: null`; empty text -> `null`.
- `bun test` must only pick up `*.test.ts` (no `.tsx` tests; Bun would compile JSX as React).
- Commit `bun.lock` (text format). Never create `package-lock.json`, `yarn.lock` or `pnpm-lock.yaml`.

## Tests (input -> expected)

- `parseLinkHeader('<http://x/v1/users?page=2&perPage=25>; rel="next", <http://x/v1/users?page=5&perPage=25>; rel="last"')` -> `{next: ..., last: ...}`; null -> `{}`
- `formatJst("2020-05-01T12:34:56.789+09:00")` -> `"2020-05-01 12:34"`; null -> `""`
- `buildQuery({status: ["draft","completed"], page: "2"})` -> `?status[]=draft&status[]=completed&page=2`
- `apiFetch` with mocked `fetch` returning 422 `{code:"validation_failed",...}` -> throws `KickflowError` with `errors`; POST with a token set includes the CSRF header; GET does not
- `apiList` parses `Page`, `Per-Page`, `Total`, `Link` headers
- `toTicketInputs` on a workflow with text, number, checkbox, master, file and calculation fields -> one entry per field with the documented value keys
